# Исправление проблемы с плейсхолдерами в AI-рекомендациях

## 📋 Описание проблемы

**Статус**: ✅ **ИСПРАВЛЕНО** (2025-07-15)

### Симптомы:
- При выборе OpenAI в качестве AI-провайдера, агенты возвращали сообщение: *"Пожалуйста, предоставьте данные для анализа, чтобы я мог приступить к выполнению задачи"*
- Плейсхолдеры вида `{forecast}`, `{hourly_sales}`, `{plan_vs_fact}` в промптах не заменялись на реальные данные
- Проблема затрагивала все AI-провайдеры (Claude, OpenAI, Gemini)

### Корневая причина:
1. **Неполная обработка MCP структуры данных**: Метод `prepareAgentData()` не корректно извлекал данные из вложенной структуры `{field: {data: [...]}}`
2. **Отсутствие обработки недостающих данных**: Плейсхолдеры для отсутствующих полей (например, `{plan_vs_fact}`) оставались незамененными
3. **Некорректная логика сжатия данных**: Метод `compressDataForTokens()` работал только с определенной структурой данных

## 🛠️ Исправления

### 1. Файл: `backend/services/multi-agent-system.js`

#### 1.1 Метод `prepareAgentData()` (строки 409-439)
**Что изменено:**
```javascript
// БЫЛО (неполная проверка):
if (mcpData[field].data !== undefined) {
    agentData[field] = mcpData[field].data;
} else {
    agentData[field] = mcpData[field];
}

// СТАЛО (корректная проверка):
if (typeof mcpData[field] === 'object' && mcpData[field].data !== undefined) {
    agentData[field] = mcpData[field].data;
} else {
    agentData[field] = mcpData[field];
}
```

**Добавлено:**
- Проверка типа объекта перед обращением к полю `.data`
- Подробное логирование подготовленных данных

#### 1.2 Метод `compressDataForTokens()` (строки 147-218)
**Что изменено:**
```javascript
// ДОБАВЛЕНА функция для универсального извлечения данных:
const extractData = (field) => {
    if (data[field]) {
        if (typeof data[field] === 'object' && data[field].data !== undefined) {
            return data[field].data;
        } else {
            return data[field];
        }
    }
    return null;
};
```

**Результат:**
- Поддержка как MCP структуры с полем `.data`, так и прямых данных
- Корректное сжатие данных для всех типов входных структур

#### 1.3 Метод `processPromptPlaceholders()` (строки 465-513) - КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ
**Что добавлено:**
```javascript
// КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ: Замена оставшихся плейсхолдеров
const remainingPlaceholders = processedPrompt.match(/\{[a-zA-Z_][a-zA-Z0-9_]*\}/g);
if (remainingPlaceholders && remainingPlaceholders.length > 0) {
    for (const placeholder of remainingPlaceholders) {
        const fieldName = placeholder.slice(1, -1);
        const noDataMessage = `[Данные "${fieldName}" отсутствуют в MCP API]`;
        processedPrompt = processedPrompt.replace(placeholder, noDataMessage);
    }
}
```

**Результат:**
- Незамененные плейсхолдеры теперь заменяются на информативные сообщения
- Исправлена регулярка для детектирования плейсхолдеров (исключая JSON скобки)
- Добавлена финальная проверка и подробное логирование

## 🔧 Устранение неполадок

### Проблема: Плейсхолдеры все еще не заменяются

**Проверить:**
1. Структуру данных от MCP API: `docker logs hr-miniapp | grep "MCP-Client"`
2. Подготовленные данные: `docker logs hr-miniapp | grep "Подготовленные данные"`
3. Процесс замены: `docker logs hr-miniapp | grep "Заменено.*плейсхолдеров"`

**Решение:**
- Проверить формат данных в MCP API
- Убедиться, что поля агентов соответствуют данным в MCP ответе

### Проблема: AI возвращает "Пожалуйста, предоставьте данные"

**Проверить:**
1. Финальный промпт: `docker logs hr-miniapp | grep "✅ Все плейсхолдеры успешно обработаны"`
2. Оставшиеся плейсхолдеры: `docker logs hr-miniapp | grep "незамененные плейсхолдеры"`

**Решение:**
- Убедиться, что все плейсхолдеры обработаны
- Проверить регулярное выражение для детектирования плейсхолдеров
