## Общая информация

### Endpoint
```
POST https://madlen.space/api/admin/schedules/import-1c
```

### Заголовки
```
Content-Type: application/json
```

### Лимиты
- Максимальный размер запроса: **500 MB**
- Рекомендуемое количество графиков за запрос: до 100
- Timeout: 120 секунд

---

## Формат запроса

### Структура JSON

```json
{
  "ДатаВыгрузки": "YYYY-MM-DD",
  "КоличествоГрафиков": <число>,
  "Графики": [
    {
      "НаименованиеГрафика": "Название графика",
      "КодГрафика": "Уникальный UUID код",
      "Организации": ["БИН1", "БИН2", "БИН3"],
      "РабочиеДни": [
        {
          "Дата": "YYYY-MM-DD",
          "Месяц": "YYYY-MM-01",
          "ВидУчетаВремени": "Тип дня",
          "ДополнительноеЗначение": <часы>,
          "ВремяНачалоРаботы": "HH:MM:SS",
          "ВремяЗавершениеРаботы": "HH:MM:SS"
        }
      ]
    }
  ]
}
```

### Описание полей

#### Корневой уровень

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `ДатаВыгрузки` | Строка | Да | Дата выгрузки данных из 1С (формат: YYYY-MM-DD) |
| `КоличествоГрафиков` | Число | Да | Количество графиков в массиве |
| `Графики` | Массив | Да | Массив графиков работы |

#### Объект "График"

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `НаименованиеГрафика` | Строка | Да | Название графика работы |
| `КодГрафика` | Строка (UUID) | Да | Уникальный идентификатор графика |
| `Организации` | Массив строк | **Нет** | **НОВОЕ!** Массив БИНов организаций (12 цифр) |
| `РабочиеДни` | Массив | Да | Массив рабочих дней графика |

**⚠️ ВАЖНО:** Поле `Организации` опциональное:
- Если передан массив БИНов - график будет связан с этими организациями
- Если не передано или пустой массив - график импортируется без связей с организациями
- БИНы должны существовать в базе данных (таблица `departments`)
- Несуществующие БИНы будут пропущены с предупреждением в ответе

#### Объект "РабочийДень"

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `Дата` | Строка | Да | Дата рабочего дня (формат: YYYY-MM-DD) |
| `Месяц` | Строка | Да | Месяц в формате YYYY-MM-01 |
| `ВидУчетаВремени` | Строка | Да | Тип дня: "Рабочий день", "В" (выходной), "О" (отпуск) и т.д. |
| `ДополнительноеЗначение` | Число | Да | Количество рабочих часов |
| `ВремяНачалоРаботы` | Строка | Нет | Время начала работы (формат: HH:MM:SS) |
| `ВремяЗавершениеРаботы` | Строка | Нет | Время окончания работы (формат: HH:MM:SS) |

```bsl
    ДанныеЗапроса.Вставить("Графики", МассивГрафиков);

    // Преобразование в JSON
    ЗаписьJSON = Новый ЗаписьJSON;
    ЗаписьJSON.УстановитьСтроку();
    ЗаписатьJSON(ЗаписьJSON, ДанныеЗапроса);
    ТелоЗапроса = ЗаписьJSON.Закрыть();

    // Создание HTTP-запроса
    Соединение = Новый HTTPСоединение(
        АдресСервера,
        443,  // HTTPS порт
        ,     // Пользователь
        ,     // Пароль
        ,     // Прокси

    );

    Запрос = Новый HTTPЗапрос(АдресAPI);
    Запрос.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
    Запрос.УстановитьТелоИзСтроки(ТелоЗапроса, КодировкаТекста.UTF8);

    Попытка
        // Отправка запроса
        Ответ = Соединение.ВызватьHTTPМетод("POST", Запрос);

        // Обработка ответа
        Если Ответ.КодСостояния = 200 Тогда

КонецПроцедуры

//
// Параметры:
//   ГрафикСсылка - СправочникСсылка.ГрафикиРаботы - график работы
//   НачалоПериода - Дата - начало периода выгрузки

//

//   Структура - данные графика для отправки
//

    График = Новый Структура;
    График.Вставить("НаименованиеГрафика", ГрафикСсылка.Наименование);
    График.Вставить("КодГрафика", Строка(ГрафикСсылка.УникальныйИдентификатор()));

    // 🆕 НОВОЕ! Получение массива организаций для графика
    МассивОрганизаций = Новый Массив;

    // Вариант 1: Если организации хранятся в табличной части графика

    ТекущаяДата = НачалоПериода;
    Пока ТекущаяДата <= КонецПериода Цикл

        КонецЕсли;

        ТекущаяДата = ТекущаяДата + 86400; // +1 день

    График.Вставить("РабочиеДни", МассивРабочихДней);

//   ГрафикСсылка - СправочникСсылка.ГрафикиРаботы

    Результат = Запрос.Выполнить();
```

### Обработка успешного ответа

```bsl
// Процедура обработки успешного ответа от сервера
//
// Параметры:
//   Ответ - HTTPОтвет - ответ от сервера
//
Процедура ОбработатьУспешныйОтвет(Ответ)

    ЧтениеJSON = Новый ЧтениеJSON;
    ЧтениеJSON.УстановитьСтроку(Ответ.ПолучитьТелоКакСтроку());
    ДанныеОтвета = ПрочитатьJSON(ЧтениеJSON);
    ЧтениеJSON.Закрыть();

    Если ДанныеОтвета.Свойство("success") И ДанныеОтвета.success = Истина Тогда

        Статистика = ДанныеОтвета.statistics;

        ТекстСообщения = СтрШаблон(
            "Импорт графиков завершен успешно:%1" +
            "- Получено графиков: %2%1" +
            "- Обработано графиков: %3%1" +
            "- Обновлено графиков: %4%1" +
            "- Вставлено рабочих дней: %5%1" +
            "- Ошибок: %6",
            Символы.ПС,
            Статистика.totalSchedulesReceived,
            Статистика.totalSchedulesProcessed,
            Статистика.totalSchedulesUpdated,
            Статистика.totalWorkDaysInserted,
            Статистика.errorsCount
        );

        // Проверка наличия ошибок
        Если ДанныеОтвета.Свойство("errors") И ДанныеОтвета.errors <> Неопределено Тогда
            ТекстСообщения = ТекстСообщения + Символы.ПС + Символы.ПС + "Предупреждения:";
            Для Каждого Ошибка Из ДанныеОтвета.errors Цикл
                ТекстСообщения = ТекстСообщения + Символы.ПС + "- " + Ошибка;
            КонецЦикла;
        КонецЕсли;

        ЗаписьЖурналаРегистрации(
            "Выгрузка графиков в HR",
            УровеньЖурналаРегистрации.Информация,
            ,
            ,
            ТекстСообщения
        );

        Сообщить(ТекстСообщения);

    Иначе
        ВызватьИсключение "Сервер вернул ошибку: " + ДанныеОтвета.error;
    КонецЕсли;

КонецПроцедуры
```

## Обработка ответа

### Формат успешного ответа (HTTP 200)

```json
{
  "success": true,
  "message": "Импорт завершен успешно",
  "statistics": {
    "totalSchedulesReceived": 10,
    "totalSchedulesProcessed": 10,
    "totalSchedulesUpdated": 3,
    "totalWorkDaysInserted": 3650,
    "errorsCount": 0
  },
  "exportDate": "2025-11-15",
  "errors": [
    "Несуществующие БИНы организаций для графика 'График 5/2': 999999999999"
  ]
}
```

### Описание полей ответа

| Поле | Тип | Описание |
|------|-----|----------|
| `success` | Boolean | Статус выполнения (true - успешно) |
| `message` | String | Текстовое сообщение о результате |
| `statistics.totalSchedulesReceived` | Number | Количество полученных графиков |
| `statistics.totalSchedulesProcessed` | Number | Количество обработанных графиков |
| `statistics.totalSchedulesUpdated` | Number | Количество обновленных графиков |
| `statistics.totalWorkDaysInserted` | Number | Количество вставленных рабочих дней |
| `statistics.errorsCount` | Number | Количество ошибок/предупреждений |
| `exportDate` | String | Дата выгрузки из запроса |
| `errors` | Array | Массив текстов ошибок/предупреждений (если есть) |

## Обработка ошибок

### Возможные ошибки

#### HTTP 400 - Bad Request
```json
{
  "success": false,
  "error": "Нет данных для импорта. Массив \"Графики\" отсутствует или пуст."
}
```

**Причины:**
- Отсутствует поле `Графики`
- Массив `Графики` пустой
- Неверный формат JSON

#### HTTP 500 - Internal Server Error
```json
{
  "success": false,
  "error": "Database connection error"
}
```

**Причины:**
- Ошибка подключения к базе данных
- Внутренняя ошибка сервера

#### Обработка ошибок в 1С

```bsl
Процедура ОбработатьОшибку(Ответ)

    ТекстОшибки = Ответ.ПолучитьТелоКакСтроку();

    Исключение
```

## 🆕 Что изменилось в API

### Новое поле "Организации"

**Ранее:** Каждый график автоматически связывался с организацией через сотрудников

**Теперь:** Можно явно указать список БИНов организаций для графика

### Преимущества нового подхода

1. **Гибкость:** Один график может использоваться в нескольких организациях
2. **Явность:** Связь графика с организациями задается напрямую
3. **Обратная совместимость:** Старый формат (без поля `Организации`) работает

### Валидация БИНов

Система автоматически проверяет:
- ✅ Существование БИНа в таблице `departments`
- ✅ Формат БИН (12 цифр)
- ⚠️ Несуществующие БИНы пропускаются с предупреждением в ответе
